# Версии и совместимость

## Совместимость версий SDK {#compatibility}

SDK находится в разработке (линия 0.0.x, статус Alpha на PyPI). Пока версия
меньше 1.0.0, несовместимое изменение возможно в любом выпуске, в том числе в
patch. Такие изменения перечислены в `CHANGELOG.md` в разделе версии
«Несовместимые изменения» или «Удалено» с указанием замены.

Публичный API — это то, что экспортирует пакет `apisdkopti24`, атрибуты сервисов
`APIClient`, сигнатуры публичных методов, модели запросов и ответов, их поля и
псевдонимы, а также классы исключений. Модули и имена с `_` в начале публичными
не считаются.

Когда это возможно, имя сначала объявляется устаревшим: SDK выдаёт
`DeprecationWarning`, CHANGELOG называет замену, а удаление происходит в одном из
следующих выпусков. Так `APISettings` устарел в 0.0.1 и удалён в 0.0.2.

Что это значит для приложения:

- закрепляйте точную версию (`apisdkopti24==0.0.5`), в промышленной среде — с
  хешами (`--require-hashes`);
- обновляйтесь только после прогона своих тестов и чтения CHANGELOG;
- запускайте тесты с `-W error::DeprecationWarning`, чтобы заметить устаревшие
  вызовы до их удаления.

С выпуска 1.0.0 SDK следует SemVer: несовместимые изменения только в major.

## Версии документации

Документация публикуется по линиям `major.minor`. Для SDK 0.0.5 используется
каталог `0.0`, а alias `latest` перенаправляет на текущую линию.

Примеры URL:

- `/apisdkopti24/0.0/`: документация линии 0.0;
- `/apisdkopti24/latest/`: перенаправление на актуальную линию;
- `/apisdkopti24/`: версия по умолчанию.

## Как работает публикация

Документация публикуется при каждом push в ветку `main`, а не только при выпуске
версии.

1. Workflow читает `project.version` из `pyproject.toml`.
2. Из версии выделяются `major.minor`.
3. `mike` собирает документацию в отдельный каталог этой линии.
4. Содержимое сохраняется в ветке `gh-pages`.
5. Alias `latest` и корневой redirect обновляются на текущую линию.
6. GitHub Pages публикует полученное дерево как неизменяемый artifact.

Patch-релиз обновляет документацию своей линии. Новый minor или major создаёт
новый каталог, поэтому документация предыдущей линии остаётся доступной.

!!! warning "Документация линии может опережать выпущенный пакет"
    Каталог `major.minor` и `latest` показывают текущее состояние `main`. Если в
    `main` есть изменения после выпуска версии этой линии, они уже видны в
    документации, но ещё не вошли в пакет. Что изменилось, но не выпущено,
    перечислено в разделе «Не выпущено» файла `CHANGELOG.md`. Проверяйте
    установленную версию через `apisdkopti24.__version__`.

## Локальная проверка

Обычная строгая сборка:

```bash
uv run mkdocs build --strict
```

Просмотр уже опубликованных версий из `gh-pages`:

```bash
git fetch origin gh-pages
uv run mike list
uv run mike serve
```

Команды `mike deploy` и `mike set-default` выполняет только GitHub Actions.
Локальная публикация не требуется и может привести к конфликту версий.

## Выпуск новой линии

1. Обновите версию SDK в `pyproject.toml` и `uv.lock`.
2. Обновите примеры, CHANGELOG и сведения о совместимости.
3. Запустите генераторы и полный release-gate.
4. Отправьте проверенный релиз в `main`.
5. Убедитесь, что `Pages` создал новую версию и обновил `latest`.

Workflow имеет право записи в репозиторий только для обновления `gh-pages` и
запускается из защищённой ветки `main`.
