# Информационная безопасность

## Изоляция credentials

Пароль передаётся через `CredentialsProvider` компоненту `DefaultAuthenticator`.
`AuthService` делегирует ему авторизацию. Остальные доменные сервисы получают только
`RequestExecutor`, read-only `SessionContext` и `SessionGate`, не хранят ссылку
на `APIClient` и не имеют доступа к его настройкам или transport.

API key отделён интерфейсом `APIKeyProvider`. `APIClient.settings` содержит только
`ConnectionSettings`; в нём отсутствуют API key, логин и пароль. `OperationExecutor`
хранит provider, а не разрешённое значение, и вызывает `get_api_key()` перед каждым
запросом. Это позволяет secret manager ротировать ключ без пересоздания клиента.
Provider не передаётся доменным сервисам.

## Передача данных

- Удалённые API-адреса должны использовать HTTPS.
- HTTP разрешён для loopback; небезопасный режим требует явного флага.
- Потоковые запросы принимают только относительные endpoint текущего API origin.
- Маршруты JSON-запросов и загрузок выбираются из `OperationSpec`; параметры пути проходят
  percent-encoding, а `/`, `\\`, `?`, `#` и dot-segments отклоняются.
- Обычный JSON-ответ больше 16 MiB по умолчанию отклоняется до декодирования.
  Значение можно изменить через `ConnectionSettings.max_json_response_bytes`
  или переменную `API_MAX_JSON_RESPONSE_BYTES`.
- SDK не обходит географические, ролевые, IP-ограничения и серверные квоты.

## Секреты

- API key, логин и пароль передаются через окружение или secret manager.
- Рекомендуемые `ConnectionSettings` не содержат credentials вообще.
- `StaticCredentialsProvider` и legacy `APISettings` скрывают значения в `repr`;
  legacy settings не сохраняется внутри клиента.
- `.env`, токены публикации и реальные session ID не должны попадать в Git.
- После случайной публикации секрет необходимо отозвать, а не только удалить
  из последнего коммита.

## Журналирование

- Request/response payload и URL с идентификаторами не журналируются.
- Logger-фильтр очищает credentials, session ID, телефоны, email, объектные ID,
  PIN/new PIN и поля безопасности QR/MPC. Очистка — дополнительная защита;
  произвольные серверные сообщения не используются в обычном выводе ошибок.
- Фильтр применяется и к logger, внедрённому пользователем.
- Каждый клиент владеет отдельными handlers; закрытие клиента не затрагивает
  logger другого клиента, а файлы открываются в append-режиме.
- `request_log_file` используется как JSONL-аудит и не содержит URL,
  path-параметров или payload.
- В логах остаются имя операции, версия, route name, HTTP/API-коды, тип ошибки и
  размер файла.

## Валидация моделей

Pydantic v2 проверяет вложенные контейнеры и fixed tuple без необработанных
`IndexError`. Дополнительные поля response сохраняются для диагностики и
совместимости, поэтому целые response-модели не следует бездумно отправлять в
логи или telemetry: неизвестные серверные поля также попадут в `model_dump()`.
Request DTO наследуют `StrictRequestModel` и отклоняют неизвестные поля, чтобы
они не попали в исходящий запрос.

## Ошибки

Сформированный SDK `APIError.context` содержит локальные сообщения и известные
типы ошибок контракта и
безопасен для стандартного `repr`. Полный ответ сервера доступен только через
явный вызов `APIError.get_raw_payload()`: он может содержать персональные или
договорные данные, поэтому его нельзя передавать в telemetry, общие логи или
внешние системы обработки ошибок.

## Повторы запросов

Автоматический повтор определяется `retry_class`: `safe` требует идемпотентности,
`network_only` допускает повторы только после сетевых ошибок, `never` запрещает их.
Авторизация использует `network_only`. Операции изменения данных с неопределённым
сетевым результатом автоматически не повторяются.
Re-auth выполняется во внешнем orchestration executor только для endpoint с
`requires_session=True`. Ошибка самой операции `auth_user` не запускает recovery,
поэтому повторный захват session lock исключён.


Встроенный текстовый formatter не выводит traceback и цепочку исключений.
Для внедрённого logger приложение должно явно установить `SafeExceptionFormatter`
или собственный безопасный formatter. Pydantic-модели используют
`hide_input_in_errors=True`; структурированные ошибки и полные модели всё равно
нельзя автоматически отправлять в журналы. Подробнее — [обработка ошибок](errors.md).
