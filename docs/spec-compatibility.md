# Совместимость со спецификацией API

Этот документ фиксирует правила SDK, которые следуют из локальной спецификации
API для корпоративных клиентов версии **1.1.60**. Примеры ключей,
идентификаторов сессий и паролей из исходного документа намеренно не переносятся
в репозиторий.

## Договорные операции

- `contracts`, `limits`, `region_limits`, `restrictions` и `templates` используют
  договор активной сессии, если `contract_id` не передан явно.
- Явный `contract_id` всегда имеет приоритет, включая методы, где спецификация
  требует заголовок договора.
- Денежные поля счёта и переводов принимаются как `Decimal` и сериализуются
  строкой.
- `productType`, `productGroup` и `regionlimit_id` нормализуются через явные
  aliases request-моделей.
- QR/MPC-функциональность сверена с отдельной спецификацией API QR версии 1.0.4
  от 30.05.2024 и не относится к изменениям раздела 2B.

## Ответы и ошибки

- Ответ рассматривается как конверт с `status`, `data` и `timestamp`.
- SDK проверяет как HTTP-статус, так и `status.code` внутри тела ответа.
- `notAuthenticated` запускает единственную повторную авторизацию и повтор запроса.
- `duplicateConflict` считается ошибкой, а не сигналом для автоматического retry.

## Расхождения фактических ответов со спецификацией

Модели ответов строятся по спецификации 1.1.60. Если API присылает другую форму, модель
ослабляется точечно, а расхождение фиксируется здесь и в тестах
`tests/test_live_response_deviations.py` (синтетические значения, реальная структура):

| Метод | Поле | Спецификация | Фактический ответ | Модель SDK |
|---|---|---|---|---|
| `get_transactions_v2`, `get_card_transactions_v2`, `get_transaction_detail` | `data.result[].stor_transaction_id` | строка, обязательное | `null` у несторнированных транзакций | <code>int &#124; str &#124; None</code> |
| `get_azs_list_v2` | `data.result[].utc_timezone` | строка, обязательное | `null` у части АЗС | <code>str &#124; None</code> |
| `get_card_detail` | `data.result[].transaction_timeout.type` | число, обязательное | буквенный код (`H`, `D`, `M`) или `null`, если таймаут не задан | <code>int &#124; str &#124; None</code> |

| `set_restriction` | `data[]` | строки | ID ограничителей числами | строки; число приводится к строке |

| `get_invoices` | `data.result[].amount`, `currency`, `date_end`, `last_update` | float / uint | строки | <code>float &#124; str</code>, <code>int &#124; str</code> |

## Расхождения фактических запросов со спецификацией

API принимает запросы, которые спецификация описывает иначе:

| Метод | Параметр | Спецификация | Фактически | SDK |
|---|---|---|---|---|
| `order_report_v1` | `email` | обязательный | запрос без `email` принят, задача отчёта создана | необязательный параметр |
| `get_info` | `period` | `YYYY-MM` или `YYYY-MM-DD` | принимает и `YYYY-MM-DD HH:MM:SS`: статистика за 24 часа от этого момента | без `period` передаёт текущие дату и время |
| `update_template` | HTTP-метод | `PUT` | POST без `_method=PUT` отклоняется с кодом 405 | по умолчанию POST с `_method=PUT`; `use_post=False` отправляет PUT |
| `update_template_limit` | тело запроса | объект лимита | массив отклоняется с кодом 405 | отправляет объект; `limits` должен содержать ровно один лимит |
| `get_final_prices`, `check_purchase` | тело запроса | JSON | в форме `goods` не принимается как массив: `400` | отправляет тело JSON |
| `create_user` | `mobile` | строка | только цифры, 11–13 знаков, без `+` | передаёт значение как есть |
| `create_template`, `update_template` | `name` | строка | не длиннее 30 символов | передаёт значение как есть |
| `set_card_group` | `name` | строка | от 1 до 50 символов; двоеточие в имени приводит к `500` | передаёт значение как есть |

## Сервер не защищает от дублей: коды ошибок и надёжность повтора

Часть операций, которые логично было бы считать защищёнными от дублирования
(создание объекта с уже занятым именем или идентификатором, повторное удаление),
не возвращают `409 duplicateConflict` и код ошибки не всегда соответствует сути
проблемы:

| Метод | Действие | Фактический ответ | Что это значит |
|---|---|---|---|
| `create_user` | повтор с тем же `mobile` | `403 accessDenied`, «Указанный логин пользователя уже существует в системе» | не `409`; проверяйте текст сообщения, а не только код |
| `set_card_group` | создание с именем, которое уже занято | `200`, создаётся вторая группа с тем же именем | уникальность имени сервер не проверяет — проверяйте список групп сами |
| `remove_card_group` | повторное удаление уже удалённой группы | может прийти `403 accessDenied` («Нет доступа») вместо `404 notFound` | не полагайтесь только на `404`, чтобы отличить «уже удалено» от запрета доступа |

Из этого следуют практические выводы, отражённые в примерах методов выше:
проверяйте состояние самостоятельным чтением до повторной отправки изменяющего
запроса, а не по коду ошибки.

## Правила сервера, которых нет в спецификации

| Метод | Наблюдение | Что учесть |
|---|---|---|
| `resend_invite` | Повторная отправка раньше чем через минуту после предыдущей, в том числе сразу после `create_invite(with_send=True)`, отклоняется ответом `429` «С момента последней попытки отправки должна пройти 1 минута». После одной успешной повторной отправки `attempts` («количество попыток повторных отправок в день») изменился с 2 на 0, `expired_at` не изменился | `429` здесь означает паузу приглашения, а не общий лимит частоты; срок приглашения продлевает только `prolong_invite` |
| `order_invoice` | Заказ счёта отвечает `data: true`; заказанный счёт появляется в `get_invoices` с задержкой — через 5 секунд после заказа его ещё не было | пустой список сразу после заказа не означает неудачу; перед повторным заказом подождите и проверьте `get_invoices` снова |
| `get_report_job_list_v1` | Задача появляется сразу после `order_report_v1`; `available_after` уменьшается как обратный отсчёт в секундах; отчёт за месяц был готов примерно через 5 минут, что согласуется с заявленными ~300 секундами | скачивайте файл, когда `available_after` станет `0` |

## DEMO: успешный ответ без выполнения операции

DEMO-стенд проверяет формат запроса и отвечает одним из двух ответов: запрос
верен или ошибка. Для части изменяющих методов успешный ответ на DEMO не означает,
что операция выполнена:

| Метод | Ответ на DEMO | Фактический эффект |
|---|---|---|
| `move_to_card`, `move_to_contract` | `data: true` | остаток кошелька не меняется |
| `order_report` | `data: {"job_id": []}` | задача отчёта не создаётся |
| `set_card_product` | `data` — список карт | продукт карты меняется сразу и виден в `get_cards_v2` |

Поэтому DEMO подходит для проверки формы запросов и ответов, но не для проверки
денежных операций и формирования отчётов — их результат виден только в рабочей
среде.

## Повтор запросов

- Безопасные операции чтения могут повторяться после временной сетевой ошибки.
- Операции изменения данных не повторяются после неопределённого сетевого сбоя.
- Авторизационные запросы разнесены минимум на 5 секунд.
- Ответы `429` и `509` повторяются только для безопасных операций.

Такой подход намеренно строже обычного retry по HTTP-методу: он исключает
повторную отправку создания, оплаты или другого изменения с неизвестным
результатом первого запроса.

## Ограничение частоты

Спецификация задаёт 2 запроса в секунду для DEMO и 5 запросов в секунду для
рабочей среды. Упреждающий лимит включён по умолчанию; переопределить частоту
можно через переменную окружения или `RateLimitPolicy` в настройках клиента
(подробнее — в разделе [«Ограничьте частоту и параллельность запросов»](configuration.md#rate-limit)):

```env
API_REQUESTS_PER_SECOND=2
```

Лимитер общий для экземпляра transport и синхронизирован между конкурентными
корутинами.

Даже при соблюдении заявленной частоты сервер иногда всё равно отвечает
`509` — значит, отправляйте запросы с запасом, а не ровно на границе лимита, и
рассчитывайте на то, что редкие `509` — штатная ситуация, а не признак сбоя
клиента. Для чтения SDK повторяет такой ответ автоматически; для изменяющих
операций — нет, поскольку `509` не гарантирует, что запрос не был обработан
(см. «Повтор запросов» выше).

## Альтернативный HTTP-метод

Для методов, где инфраструктура не пропускает `PUT` или `DELETE`, SDK
поддерживает `POST` с `_method=PUT` или `_method=DELETE`. Параметр `use_post`
доступен в операциях пользователей, приглашений и шаблонов. Исходный payload
копируется и не изменяется.

## Registry

Registry содержит `OperationSpec`, объединяющий response type, HTTP-маршрут,
версию API, demo-доступность, timeout, idempotency и класс retry. Каталог
собирается из экспортированных спецификаций доменных модулей без AST-разбора.

Независимый контракт, однократно преобразованный из свода методов, находится в
`specifications/api-methods.yaml`. Команда
`python scripts/verify_external_contract.py specifications/api-methods.yaml`
строго сверяет `external_code`, operation, route name, HTTP-метод, версию, путь,
DEMO-доступность и тарификацию с registry. Исходный Excel остаётся вне
репозитория. Для `calculate_prices` и `check_purchase` в YAML явно зафиксировано
расхождение: сводная таблица указывает `GET`, но наличие request body в детальной
спецификации требует `POST`.

Расширенный контракт `specifications/api-contract-v1.1.60.yaml` однократно
сформирован из DOCX-спецификации 1.1.60. Он дополнительно фиксирует параметры и
типы запросов, обязательность полей, aliases request-моделей, response schemas и
санитизированные официальные примеры. Исходный DOCX и секреты из примеров в
репозитории не хранятся. CI сверяет этот контракт с `OperationSpec`, публичными
сигнатурами сервисов и Pydantic schemas.

Для QR/MPC-операций `MPC`, `pay`, `initMPC`, `confirmMPC`, `updateMPC`,
`deleteMPC` и `resetMPC` используется отдельный первичный источник —
спецификация сервиса API QR версии 1.0.4. Из неё взяты обязательность параметров,
ограничения PIN и устройства, структура списка МПК и ответ генерации платёжной
строки. Секреты и действующие идентификаторы из примеров источника в репозиторий
не переносятся.

## Границы ответственности

Географические ограничения, срок жизни сессии и серверные квоты контролируются
API. SDK не пытается обходить эти ограничения, а только нормализует ошибки и
снижает вероятность лишних запросов.
