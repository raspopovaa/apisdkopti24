# Оплата по QR-коду

SDK поддерживает полный жизненный цикл мобильного профиля карты (МПК): выпуск,
подтверждение по SMS, генерацию платёжной строки, обновление, удаление и сброс
счётчиков. Методы находятся в `client.virtual_cards` и используют API v2.

Примеры ниже используют условные идентификаторы и не содержат credentials.

## Среды и тарификация

QR API описан отдельной спецификацией QR 1.0.4 и работает на QR-тестовом стенде и
на рабочем сервере; на DEMO его нет. Тестовый стенд QR заполнен данными клиента,
не тарифицируется и может работать нестабильно. Для него создайте отдельный
`APIClient` со своим `base_url` и учётными данными — не смешивайте их с рабочими.
Методы QR в каталоге SDK не тарифицируются. На сервере они пока не проверены:
доступа к QR-тестовому стенду не было.

## Подготовка МПК

Карта должна быть привязана к указанному пользователю. На одной карте может
существовать только один МПК: существующий профиль сначала удалите через
`delete_mpc`. Выпуск идёт в два шага — `init_mpc`, затем `confirm_mpc` с кодом из
SMS, который придёт на телефон пользователя.

!!! warning "Неверный SMS-код блокирует выпуск"
    Ошибка в коде `confirm_mpc` блокирует выпуск МПК по карте. SDK не повторяет
    подтверждение автоматически: не перебирайте коды. Блокировку снимает
    администратор через `reset_mpc` (см. ниже).

```python
await client.virtual_cards.init_mpc(
    card_id="card-id",
    user_id="user-id",
    pin="1234",
    device_id="device-id",
    device_name="Driver phone",
)

await client.virtual_cards.confirm_mpc(
    card_id="card-id",
    code="432245",
)
```

`pin` должен содержать от 4 до 8 цифр. `device_id` допускает от 1 до 255
символов, `device_name` — от 11 до 17 символов. SDK проверяет эти ограничения, PIN
и SMS-код до входа и сетевого запроса; сообщения об ошибках проверки не содержат
введённых значений. PIN и SMS-код нельзя сохранять в логах или telemetry.

Договор для `init_mpc`, `confirm_mpc`, `update_mpc`, `delete_mpc` и `reset_mpc` —
`contract_id` или выбранный договор сессии; SDK передаёт его заголовком
`contract_id`, что спецификация разрешает наравне с телом запроса.

## Формирование платёжного QR-кода

```python
from time import time

payment = await client.virtual_cards.generate_payment_qr(
    card_id="card-id",
    pin="1234",
)

if payment.end_date <= int(time()):
    raise RuntimeError("Платёжная строка уже недействительна")

qr_payload = payment.code
```

Договор методу не нужен: в спецификации QR у генерации кода оплаты его нет. SDK
передаёт заголовок `contract_id`, только если договор указан явно или выбран в
сессии.

API возвращает строку BER-TLV в `payment.code`, но не растровое изображение.
Передайте эту строку выбранной библиотеке отображения QR-кодов. Не преобразуйте
и не сокращайте значение: кассовая система должна получить его без изменений.

Платёжная строка действует не более 10 минут. Всегда проверяйте `end_date`
непосредственно перед показом или оплатой и выпускайте новую строку после
истечения срока. Не кэшируйте её и не передавайте в логи.

Поля `transaction_count` и `tries` показывают число использованных и максимально
доступных попыток. Когда `transaction_count` достигает `tries`, сервер
автоматически перевыпускает МПК. Не сбрасывайте и не пересчитывайте эти счётчики
на своей стороне — используйте значения из ответа.

`end_date` спецификация называет «сроком жизни платёжной строки» без единиц; по
примеру ответа это Unix-время окончания действия.

Платёжная строка, номер карты и ID устройства не попадают в `repr` моделей
ответа, а ключи `code`, `pin`, `card_number` и `device_id` скрываются в журналах
SDK. Не записывайте сами значения в свои журналы.

!!! warning "Неверные секретные значения блокируют оплату"
    Оплата с неверными секретными значениями МПК блокирует оплату по карте.
    Если при оплате возникают ошибки или нужно сменить PIN, перевыпустите МПК
    через `update_mpc`; блокировку снимает `reset_mpc`. Не повторяйте оплату
    вслепую.

## Управление профилем

```python
# Перевыпустить ключи без смены PIN.
await client.virtual_cards.update_mpc(card_id="card-id", pin="1234")

# Перевыпустить ключи и изменить PIN.
await client.virtual_cards.update_mpc(
    card_id="card-id", pin="1234", new_pin="4321"
)

# Сбросить блокировку оплаты или выпуска. Какой тип счётчика снимает какую
# блокировку, спецификация не уточняет; по умолчанию — ResetCounterCode.
await client.virtual_cards.reset_mpc(
    card_id="card-id", type_="ResetCounterCode"
)
await client.virtual_cards.reset_mpc(
    card_id="card-id", type_="ResetCounterMPC"
)

# Удалить профиль.
await client.virtual_cards.delete_mpc(card_id="card-id")
```

Операции изменения МПК не повторяются автоматически после неопределённого
сетевого сбоя. Сначала запросите список профилей и проверьте состояние карты.

## Список выпущенных МПК

```python
profiles = await client.virtual_cards.get_mpc_qr_list()

for profile in profiles.result:
    print(profile.card_id, profile.use_mpc, profile.transaction_count, profile.tries)
```

Без `contract_id` API возвращает все МПК клиента: этот метод не подставляет
договор сессии. Явно передайте
`contract_id`, если приложению разрешено работать только с одним договором.
