# Валидация исходящих запросов

SDK проверяет параметры до обращения к API. Источником типов, обязательности и
описаний служат таблицы «Параметры запроса» спецификаций 1.1.60 и QR 1.0.4.

## Как устроена проверка

Публичный метод проверяет аргументы строгой Pydantic-моделью или отдельными
функциями валидации. Модель запрещает неизвестные поля, проверяет типы и
межполевые условия; функции проверяют идентификаторы, периоды и пагинацию.
После проверки сервис размещает параметры в одной
из частей `RequestOptions`: `path_params`, `query`, `form`, `json_body` или
`headers`. `OperationSpec.request` содержит единый `RequestContract`, который
запрещает передавать тело или query операции, если они не предусмотрены её
wire-контрактом, и перечисляет применимые DTO в `request_models`.

Вложенные фильтры АЗС и пользователей передаются серверу JSON-строкой внутри
query. SDK сначала валидирует объект `AzsV1Filter`, `AzsV2Filter` или
`UserFilter`, затем сериализует его. Для `set_limit` каждый `LimitRequestItem`
проверяет цель (`card_id` либо `group_id`) и наличие денежного или объёмного
лимита до формирования form-поля `limit`.

QR/MPC-модели дополнительно проверяют PIN из 4–8 цифр, длину данных устройства,
допустимый тип сброса и условие выпуска виртуальной карты: необходимо передать
ровно одно из `type_` и `template_id`.

## Выбор модели

| Вид операции | Механизм |
|---|---|
| Без параметров | DTO не создаётся; проверяется только `RequestContract` |
| Один path-параметр | общий непустой тип идентификатора |
| Период или пагинация | общие `PaginationQuery`, `OffsetPaginationQuery`, `DateRangePaginationQuery` |
| Фильтры | отдельная query-модель и вложенная модель фильтра |
| Мутация, form или JSON | отдельный строгий request DTO |
| Бинарная загрузка | строгие path/query-параметры; ответ проверяется транспортом |

Полный машинный каталог полей request DTO находится в
`specifications/request-models-v1.1.60.json`. Его создаёт
`scripts/export_request_models.py`. Runtime-форма запросов берётся из единого
`operation-catalog.json`, а матрица `request-matrix-v1.1.60.json` и
параметризованный тест собирают `PreparedRequest` для всех 89 операций и
сравнивают method, version, path, query, form, JSON, headers и `Content-Type` до
сетевого вызова.

## Ошибки валидации

Некорректные параметры могут вызвать `pydantic.ValidationError`,
`RequestValidationError`, а в отдельных проверках — `ValueError` или `TypeError`.
Проверки выполняются до отправки основного запроса. Некоторые методы сначала
разрешают контекст договора и могут выполнить отложенную авторизацию; поэтому
ошибка параметров не всегда означает отсутствие любых сетевых запросов.
Это локальная проверка SDK; она не заменяет серверные проверки прав,
принадлежности объекта договору, квот и актуального состояния данных.

Сообщения собственных валидаторов SDK написаны по-русски. Стандартный текст
`pydantic.ValidationError` формирует Pydantic; он может содержать английские
формулировки. Для безопасной русскоязычной диагностики используйте
`classify_exception(exc).error_message`, не выводя исходные значения полей.

Подробнее: [обработка ошибок](errors.md).
