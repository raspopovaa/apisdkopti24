# `DocumentItem`

Информация об одном первичном документе.

!!! info "Назначение Pydantic"
    Тип модели: **response/data**. Ответ API проверяется этой моделью напрямую или рекурсивно как часть родительской response-модели. При несовпадении типов или отсутствии обязательного поля Pydantic формирует `ValidationError`.

## Поведение модели

| Настройка | Значение | Фактическое поведение |
|---|---|---|
| Дополнительные поля (`extra`) | `allow` | Дополнительные поля разрешены и сохраняются в модели. |
| Проверка default | `True` | Значения по умолчанию также проходят валидацию. |
| Заполнение по имени поля | `True` | Разрешено использовать имя поля наряду с alias. |
| Число → строка | `False` | Для строковых полей числовые значения могут быть преобразованы в строку. |

## Поля и проверки

| Поле | Тип после валидации | JSON-тип | Обязательное | `None` | По умолчанию | Описание | Ограничения схемы | Что проверяет Pydantic |
|---|---|---|:---:|:---:|---|---|---|---|
| `id` | <code>str</code> | <code>string</code> | Да | Нет | <code>—</code> | Уникальный идентификатор документа (UUID) | — | Значение преобразуется и проверяется как str. |
| `name` | <code>str</code> | <code>string</code> | Да | Нет | <code>—</code> | Название документа, например 'УПД' | — | Значение преобразуется и проверяется как str. |
| `name_doc` | <code>str &#124; None</code> | <code>string &#124; null</code> | Нет | Да | <code>None</code> | Системное имя документа, например 'СчетФактураВыданный' | — | Значение должно соответствовать одному из типов: str, None |
| `number` | <code>str</code> | <code>string</code> | Да | Нет | <code>—</code> | Номер документа, например 'CSC0000000533998' | — | Значение преобразуется и проверяется как str. |
| `date` | <code>int</code> | <code>integer</code> | Да | Нет | <code>—</code> | Дата документа в формате UNIX timestamp | — | Значение преобразуется и проверяется как int. |
| `total` | <code>float</code> | <code>number</code> | Да | Нет | <code>—</code> | Общая сумма документа | — | Значение преобразуется и проверяется как float. |
| `vat` | <code>float</code> | <code>number</code> | Да | Нет | <code>—</code> | Сумма НДС | — | Значение преобразуется и проверяется как float. |
| `sum` | <code>float</code> | <code>number</code> | Да | Нет | <code>—</code> | Сумма без НДС | — | Значение преобразуется и проверяется как float. |
| `currency` | <code>str</code> | <code>string</code> | Да | Нет | <code>—</code> | Валюта документа, например 'руб.' | — | Значение преобразуется и проверяется как str. |
| `consignee` | <code>str &#124; None</code> | <code>string &#124; null</code> | Нет | Да | <code>None</code> | Грузополучатель (организация) | — | Значение должно соответствовать одному из типов: str, None |
| `contract_id` | <code>str</code> | <code>string</code> | Да | Нет | <code>—</code> | ID договора, к которому относится документ | — | Значение преобразуется и проверяется как str. |
| `contract_name` | <code>str</code> | <code>string</code> | Да | Нет | <code>—</code> | Номер или название договора | — | Значение преобразуется и проверяется как str. |

!!! note "Граница проверки"
    Значения, упомянутые только в тексте описания, не считаются жёстким ограничением. Например, фраза «Y или N» проверяется только тогда, когда в модели задан `Literal`, Enum, ограничение `Field` или пользовательский валидатор.
