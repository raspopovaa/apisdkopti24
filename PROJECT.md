# GPN API Client — контекст проекта

## Состояние

- Пакет: `apisdkopti24`.
- Текущая версия: `3.3.5` (источник истины — `pyproject.toml`).
- Python: `>=3.11,<3.15`.
- Статус: разработка; публикация в TestPyPI, production-применение только после проверки интеграции.
- Репозиторий: `raspopovaa/apisdkopti24`.

## Цель

Типизированный асинхронный Python SDK корпоративного API топливных карт. SDK скрывает HTTP, авторизацию, состояние сессии, retry/rate-limit и декодирование ответов за доменными сервисами `client.<domain>`.

## Источники истины

При расхождениях сначала зафиксировать конфликт, не исправлять его догадкой:

1. Безопасность, ограничения среды и явные решения владельца проекта.
2. Актуальные официальные документы в `docs/specifications/`, включая QR 1.0.4.
3. Нормализованные контракты в `specifications/` и runtime registry.
4. Публичные сигнатуры, модели и тесты.
5. Сгенерированная документация и README.

Основная спецификация: API корпоративного клиента 1.1.60 от 2025-10-01. QR-спецификация 1.0.4 используется при анализе и реализации. Очищенные исходные документы имеют суффикс `.sanitized`.

## Реализованные области

`auth`, `card_groups`, `cards`, `contracts`, `dictionaries`, `ewallet`, `final_prices`, `invites`, `limits`, `region_limits`, `reports`, `restrictions`, `templates`, `transactions`, `users`, `virtual_cards`.

## Технические правила

- Только асинхронный I/O через `httpx` и существующий transport.
- Публичные ответы — типизированные Pydantic-модели.
- Параметры публичных методов — keyword-only, если существующий стиль не требует иного.
- Endpoint добавляется в registry/контракт, затем в сервис, модели, тесты и документацию.
- Секреты доступны только через providers; не хранить их в настройках сервисов и логах.
- Реальные запросы, публикация, изменение версии и Git-операции требуют явного разрешения.

## Состояние QR

Каталог содержит 89 операций, включая подтверждённые МПК/QR-операции из
контракта QR 1.0.4. Их статус определяется реализацией, контрактными fixtures и
тестами, а не только наличием похожих методов виртуальных карт.

## Definition of Done

Изменение завершено, когда контракт подтверждён источником, код типизирован, секреты не раскрываются, тесты покрывают успех и ошибки, проходят `pytest`, `ruff`, `black --check`, `mypy` и contract-аудиты, а документация и CHANGELOG обновлены.
