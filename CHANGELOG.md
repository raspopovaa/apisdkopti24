# История изменений

## 3.4.4 — 2026-09-28

### Документация

- `create_user`: повтор `mobile` завершается `403 accessDenied` («Указанный логин
  пользователя уже существует в системе»), а не `409 duplicateConflict` — пример
  ошибки исправлен;
- `set_card_group`: имя группы не обязано быть уникальным, сервер создаёт вторую
  группу с тем же именем без ошибки — прежний пример `409 duplicateConflict`
  убран; добавлены ограничения на имя (1–50 символов, двоеточие → `500`);
- `set_cards_to_group`, `get_card_groups`: состав группы применяется не сразу —
  `status` и `cards_count` могут быть пустыми ещё несколько десятков секунд;
- `remove_card_group`: ответ заметно медленнее прочих изменяющих методов;
  повторное удаление уже удалённой группы может прийти как `403 accessDenied`,
  а не `404 notFound`;
- `get_final_prices`, `check_purchase`: отказ процессинга приходит как
  `403 accessDenied` с кодом причины только в тексте сообщения — добавлен пример
  и предупреждение не проверять по этому ответу `api_key` или роль;
- `create_invite`: формат `mobile` отличается от `create_user` (здесь принимается
  `+7…`, там — нет);
- `spec-compatibility.md`: новый раздел о случаях, где сервер не защищает от
  дублей, и уточнение про `509` при соблюдении заявленной частоты запросов.

## 3.4.2 — 2026-09-28

### Исправлено

- `get_cards_v1`: поля `can_work_offline`, `card_auth_type` и `date_expired`
  необязательны — API присылает их не для всех карт;
- `get_card_detail`: `card_auth_type` допускает `null`;
- `get_users`: `contracts[].cards_count` необязательно;
- `set_restriction`: числовые ID созданных ограничителей приводятся к строкам;
- `update_template`: по умолчанию отправляется POST с `_method=PUT` — POST без

### Изменено

- несоответствие ответа модели выбрасывает `ResponseValidationError` (наследует
  `ValueError`) вместо `pydantic.ValidationError`: текст однострочный, без значений
  из ответа, пути полей в `problems`, исходная ошибка в `__cause__`.

### Документация

- `get_azs_list_v2`: всегда передавайте `page` и `on_page` — вся сеть АЗС одним
  ответом превышает предел размера по умолчанию;
- `detach_card`: для непривязанной карты API отвечает `403 accessDenied`.

## 3.4.0 — 2026-09-27

### Исправлено по сверке со спецификацией

- `create_virtual_card(contract_id=...)` падал с `RequestPreparationError` до
  отправки запроса: каталог операций не разрешал заголовок `contract_id`, а сервис
  его передавал. Договор теперь передаётся в форме и в заголовке;
- `release_virtual_card` принимает `contract_id`, как описано в спецификации.
  Без него SDK передаёт в заголовке договор, выбранный при авторизации, а не
  оставляет выбор серверу;
- `get_invites` принимает `filter` из спецификации и передаёт его строкой JSON;
- `get_final_prices` проверяет, что `poi_id` не пустой и передан хотя бы один
  товар, до отправки запроса;
- в `docs/spec-compatibility.md` добавлены расхождения запросов со
  спецификацией: `order_report_v1` принимает запрос без `email`,
  `get_info` принимает `period` с датой и временем.

### Добавлено

- раздел документации «Учебные примеры»: для каждого метода — запускаемый пример
  `examples/methods/<домен>/<метод>.py` и страница с HTTP-запросом, ответом,
  ошибками API и ошибками до отправки запроса. Запросы и тексты исключений
  записываются генератором `scripts/generate_method_examples.py` при выполнении
  примера на подставном транспорте; CI проверяет, что примеры актуальны. Примеры
  есть для всех 89 методов. На каждой странице — описания параметров, модели
  запроса и ответа с путями в JSON и типами по спецификации, а также особенности
  метода: статус контракта, известные расхождения API со спецификацией, параметры
  спецификации, которые SDK не передаёт, и пример запроса из спецификации;
- исключения API (`APIError`, `ValidationError`, `NotAuthenticatedError`,
  `AccessDeniedError`, `NotFoundError`, `DuplicateConflictError`,
  `RateLimitError`, `ServerError`) импортируются из корня пакета: пример
  `from apisdkopti24 import APIError` в документации раньше падал с `ImportError`;
- `tools/live_check/` — по одному запускаемому скрипту для каждого из 89
  методов, с записью запроса и ответа в `results/`. Параметры задаются в
  `test_data.json` (`common`, `methods`, `overrides`), файлы методов генерируются
  и проверяются в CI.

### Удалено

- `examples/check_all_89_real_api.py` и `examples/check_all_89_auto.py`: их
  заменяет `tools/live_check/`.

### Изменено

- описание пакета, ключевые слова PyPI, README и заголовок документации явно
  называют Opti24 API и API топливных карт АЗС, чтобы проект находился
  поиском;
- по умолчанию SDK больше не создаёт `./api.log` и `./api_requests.jsonl`:
  файлы журнала включаются явно через `LOGGER_FILE`/`REQUEST_LOG_FILE` или
  `logger_file`/`request_log_file`. Без них сообщения идут в логгер
  `apisdkopti24.client`, вывод настраивает приложение;
- пустые переменные окружения (`API_MAX_IN_FLIGHT=` и т. п.) снова означают
  значение по умолчанию, а не ошибку конфигурации;
- параметр `limit_response_size` в `operation()`, `OperationSpec` и
  `PreparedRequest` объявлен устаревшим: он ни на что не влияет, а передача
  `limit_response_size=False` выдаёт `DeprecationWarning`.

### Исправлено

- `cards.block_card` передаёт список карт одним полем `card_id` со строкой
  JSON-массива, как в спецификации 1.1.60. Раньше SDK отправлял повторяющиеся
  поля `card_id`, из которых сервер брал только последнюю карту и отвечал
  успехом: при блокировке нескольких карт остальные оставались активными;
- ответ 401 на запрос, отправленный со старой сессией, больше не вызывает
  повторную авторизацию, если параллельный запрос уже восстановил сессию:
  раньше свежая сессия сбрасывалась и авторизация повторялась;
- закрытие клиента с файловым журналом удаляет его logger из реестра `logging`:
  создание многих клиентов больше не накапливает память.

### Безопасность

- workflow публикации запускает тесты перед сборкой, берёт версию из собранного
  пакета и прерывается, если такая версия уже есть в TestPyPI: smoke-тест всегда
  проверяет тот же пакет, который затем уходит в PyPI;
- локальные данные (`tools/live_check/test_data.json`,
  `tools/live_check/results/`) исключены из git.

## 3.3.9 — 2026-09-25

### Изменено

- `str(APIError)` снова выводит сообщение сервера из `status.errors[].message`
  («Сообщение сервера: …») рядом с локальным сообщением и подсказкой. Текст
  очищается: управляющие символы, email, телефоны и значения `ключ=значение`
  удаляются, сообщения с чувствительными полями заменяются целиком. Очищенные
  сообщения доступны в `APIError.server_messages`; в audit и `context.messages`
  по-прежнему только локальное сообщение.
- Проверочный сценарий `examples/check_all_89_real_api.py` сохраняет ответы рядом
  с `LOGGER_FILE`, дополняет каждую запись описанием метода, введёнными параметрами
  и описаниями полей, а в выводе ответа больше не скрывает `code` (код статуса или
  товара); SMS-код в запросах по-прежнему скрыт.

## 3.3.8 — 2026-09-25

### Добавлено

- `APIConnectionError` (код audit `network_connect_failed`): SDK сообщает, что
  соединение с сервером API не установлено, указывает хост и разрешённые для API
  страны (RU, BY, KZ, TJ, KG, IQ, AE, RS). Раньше такой отказ выглядел как общий
  `OperationTimeoutError` без причины;

  соединения, чтобы недоступный сервер не занимал весь timeout попытки.

### Исправлено

- `OperationTimeoutError`, возникший после сетевой ошибки, сохраняет её в `__cause__`.

- отдельный контракт QR API 1.0.4 и руководство по безопасной QR-оплате.

### Изменено

- QR/MPC-методы используют явные параметры вместо нетипизированного `payload`;
- ответы списка МПК и генерации оплаты валидируются специализированными моделями.

## 3.0.3 — 2026-09-06

## 3.0.0 — не выпущено

### Изменено

- `APIClient.session_id` и `APIClient.contract_id` стали read-only;
- добавлены `select_contract()`, `restore_session()` и `clear_session()`;
- retry ограничен общим deadline и единым attempt budget;
- retry backoff использует full jitter;
- публичные сервисы раньше отклоняют пустые ID, списки и неверную пагинацию.

### Исправлено

- batch-операции лимитов и ограничений больше не допускают смешанные договоры;
- timeout попытки не может превышать оставшееся время общей операции.
