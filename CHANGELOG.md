# История изменений

## 3.3.8 — 2026-09-25

### Добавлено

- `APIConnectionError` (код audit `network_connect_failed`): SDK сообщает, что
  соединение с сервером API не установлено, указывает хост и разрешённые для API
  страны (RU, BY, KZ, TJ, KG, IQ, AE, RS). Раньше такой отказ выглядел как общий
  `OperationTimeoutError` без причины;
- `TimeoutPolicy.connect` (по умолчанию 10 с) — отдельный лимит на установку
  соединения, чтобы недоступный сервер не занимал весь timeout попытки.

### Исправлено

- `OperationTimeoutError`, возникший после сетевой ошибки, сохраняет её в `__cause__`.

## 3.3.7 — 2026-09-25

### Изменено

- `dictionaries.get_dictionary` больше не ограничивается `max_json_response_bytes`:
  большие справочники не приводят к `ResponseTooLargeError`; добавлен признак
  операции `OperationSpec.limit_response_size`.

## 3.3.6 — 2026-09-25

### Изменено

- собственные сообщения ошибок, журналов и служебных скриптов, комментарии и
  строки документации приведены к русскому языку; машинные коды и поля API сохранены;
- уточнены подсказки о повторах запросов, смысл общего таймаута, правила
  валидации и параметры конфигурации;
- обновлён справочник API из исходников, удалены повторные блоки метаданных страниц.

## 3.3.5 — 2026-09-25

### Безопасность

- серверные сообщения ошибок заменены локальным каталогом; неизвестные типы
  ошибок не попадают в публичный контекст и audit; raw payload доступен явно;
- добавлена очистка PIN/new PIN и QR/MPC-полей, безопасный formatter traceback
  и скрытие входных значений в тексте Pydantic validation errors.

### Исправлено

- повреждённое поле типа ошибки больше не ломает обработчик и audit;
- локальные ошибки периода используют RequestValidationError без HTTP-кода
  и проверяются до ленивой авторизации транзакционных запросов;
- текстовый audit содержит код, причину и correlation ID; сбой logging handler
  не заменяет исходную ошибку операции.

### Изменено

- добавлен ErrorContext.transient; прежний retryable остаётся признаком
  временной ошибки, а разрешение повторов определяется политикой операции.

## 3.3.4 — 2026-09-24

### Безопасность

- обычные JSON-ответы ограничены 16 MiB по умолчанию до декодирования;
- CI выполняет аудит runtime-зависимостей через `pip-audit`;
- Dependabot отслеживает Python-зависимости и GitHub Actions.

### Изменено

- CI, документация, Pages и TestPyPI build устанавливают зависимости из
  `uv.lock` через `uv sync --frozen`;
- версия пакета читается из distribution metadata вместо дублирования в
  `apisdkopti24.__init__`;
- `APIClient` больше не принимает неисполняемый пользовательский `registry`;
  `client.registry` остаётся каталогом для инспекции;
- Ruff и Black используют единый line length 100;
- добавлен файл лицензии MIT и очищена security-документация.


## 3.3.3 — 2026-09-09

### Изменено

- устранено дублирование сборки `RequestOptions` для JSON- и streaming-запросов;
- декодирование типизированных JSON-ответов централизовано в `OperationExecutor`;
- публичные методы и wire-формат запросов не изменены.

## 3.3.0 — 2026-09-06

### Изменено

- request metadata включена в единый `OperationSpec`, а `EndpointSpec` удалён;
- внутренние поля запроса переименованы в `query`, `form` и `json_body`;
- удалён legacy-вход `AsyncTransport`: transport принимает только `PreparedRequest`;
- `Content-Type` формируется только для фактически переданного тела;
- повторяющиеся части query/form вынесены в типизированные request DTO;
- добавлена фиксированная wire-матрица и параметризованная проверка всех 89 операций.
- `RequestContract` заменил прежнее имя `RequestSpec` (старое имя оставлено как alias);
- добавлены строгие DTO для карт v2, АЗС v1/v2, пользователей, лимитов и QR/MPC;
- вложенные query-фильтры валидируются перед JSON-сериализацией;
- каталог 50 request-моделей генерируется и проверяется в CI;
- выпуск карты через `/release` проверяет требование ровно одного из `type_` и
  `template_id`, установленное спецификацией.

## 3.2.1 — 2026-09-06

- добавлена полная матрица запросов и ответов для 89 операций;
- модели данных приведены к типам, описаниям и обязательности полей спецификаций 1.1.60 и QR 1.0.4;
- исправлены нормализованные пути вложенных полей и алиасы wire-ответов;
- расширены контрактный аудит и проверки документации.

## 3.2.0 — 2026-09-06

### Изменено

- маршрут, response-модель и политики выполнения объединены в `OperationSpec`;
- параметры вызова и transport-запрос представлены `RequestOptions` и
  `PreparedRequest` вместо нетипизированного `**kwargs`;
- retry, rate limiting и атомарная файловая запись вынесены из `AsyncTransport`;
- executor-протоколы разделены для JSON, байтовых и файловых ответов;
- удалён дублирующий `_ServiceFacade`, при сохранении совместимого `client.cards`;
- `TemplatesService` разделён на четыре узкие внутренние группы операций;
- provisional-контракты не повышались без подтверждения первичным источником;
  полный audit остаётся очередью дальнейшей типизации.

## 3.1.1 — 2026-09-06

### Изменено

- публичный Python-модуль переименован из `apisdkopti24` в `apisdkopti24`;
- примеры, документация, тесты и контрактные ссылки обновлены для нового импорта.

## 3.1.0 — 2026-09-06

### Добавлено

- типизированный жизненный цикл МПК и формирование платёжной BER-TLV строки для QR-кода;
- локальная проверка PIN, типа сброса и длины параметров устройства;
- отдельный контракт QR API 1.0.4 и руководство по безопасной QR-оплате.

### Изменено

- QR/MPC-методы используют явные параметры вместо нетипизированного `payload`;
- ответы списка МПК и генерации оплаты валидируются специализированными моделями.

## 3.0.3 — 2026-09-06

### Исправлено

- синхронизированы публичные сигнатуры транзакций с контрактом API 1.1.60;
- обновлены тестовые ответы авторизации для строгих response-моделей;
- удалены конфликтные копии файлов и добавлена CI-защита от их повторного появления.

## 3.0.0 — не выпущено

### Изменено

- `APIClient.session_id` и `APIClient.contract_id` стали read-only;
- добавлены `select_contract()`, `restore_session()` и `clear_session()`;
- retry ограничен общим deadline и единым attempt budget;
- retry backoff использует full jitter;
- публичные сервисы раньше отклоняют пустые ID, списки и неверную пагинацию.

### Исправлено

- batch-операции лимитов и ограничений больше не допускают смешанные договоры;
- timeout попытки не может превышать оставшееся время общей операции.
