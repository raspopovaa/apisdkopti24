# Ручная проверка методов SDK на реальном API

В этой папке лежит по одному файлу на каждый из 89 методов SDK. Каждый файл
вызывает один метод на реальном API. Он показывает фактический HTTP-запрос и ответ,
проверяет ответ моделью SDK и сохраняет результат в `results/`.

## Подготовка

1. Скопируйте `test_data.example.json` в `test_data.json` и заполните своими
   значениями:
   - `common` — общие данные: договор, карта, пользователь, шаблон, период и т. д.;
   - `methods` — данные конкретных методов: тела запросов, суммы, PIN, коды из SMS;
   - `overrides` — замена любых параметров вызова конкретного метода, в том числе
     необязательных, например `{"get_info": {"period": "2026-09"}}`.

   Значения в угловых скобках (`<card_id>`) — заглушки. Метод, которому нужна
   незаполненная заглушка, не запустится и напишет, что заполнить. `test_data.json`
   в git не попадает.
2. Положите `.env` с `API_BASE_URL`, `API_KEY`, `API_LOGIN` и `API_PASSWORD` в
   `tools/live_check/` или в корень репозитория. Можно указать путь явно:
   `export APISDK_ENV_FILE=/путь/к/.env`.
3. Установите SDK из репозитория: `pip install -e . pyyaml`.

## Запуск

```bash
python tools/live_check/get_card_transactions_v2.py
```

- Перед вызовом скрипт авторизуется с `common.contract_id`, после вызова выходит
  из сессии.
- Методы, которые изменяют данные или тарифицируются, запрашивают подтверждение:
  введите `yes`.
- Параметры вызова лежат в словаре `PARAMS` в начале файла. Файлы методов создаёт
  генератор, а CI проверяет, что они совпадают с его выводом, поэтому меняйте
  значения в `test_data.json` (`methods` или `overrides`), а не в файле метода.
- В начале каждого файла описано, что делает метод, какой HTTP-запрос отправляет,
  какие параметры нужны, какие модели проверяют запрос и ответ и какие бывают
  ошибки.

## Результаты

Итог выводится одной строкой:

- `УСПЕХ` — ответ прошёл проверку модели SDK;
- `ОШИБКА МОДЕЛИ` — HTTP-ответ получен, но не совпал с моделью: выводятся поле,
  тип ошибки и значение;
- `ОШИБКА` — ошибка API с кодом и сообщением сервера, сетевая ошибка или
  локальная проверка SDK.

Файл `results/<метод>-<дата-время>.json` содержит параметры, запрос, полный ответ,
итог и список несовпавших полей. Скрыты только секреты и номер карты: API key,
session ID, логин, пароль, PIN, SMS-код, ID устройства, платёжные данные QR и
`card_number`. В результатах есть договорные данные, не публикуйте их.

## Обновление файлов методов

Файлы методов собирает генератор из метаданных SDK и спецификаций. После изменения
SDK пересоберите их:

```bash
python tools/live_check/_generate.py --force
```

`--force` перезаписывает файлы методов, в том числе ваши правки в `PARAMS`. Храните
значения в `test_data.json`, чтобы они не терялись. Проверить, что файлы актуальны:

```bash
python tools/live_check/_generate.py --check
```

Краткие описания проверок, которые попадают в `DESCRIPTION`, лежат в
`descriptions.yaml`.

Учебные примеры для документации — отдельный инструмент:
`examples/methods/` и `scripts/generate_method_examples.py`. Живая проверка здесь
нужна, чтобы сверить SDK с реальным API; учебные примеры — чтобы научиться им
пользоваться.
